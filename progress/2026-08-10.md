### 第二轮：修手机端弹窗层级 + 删「保存设置并刷新页面」

先做了一轮前端体检（设置与各功能弹窗），列了 8 条，用户挑了两条先修。

**手机上设置弹窗被侧栏抽屉盖住（功能性 bug）**

`.modal-backdrop` 是 `z-index: 30`，而 ≤1100px 时侧栏抽屉是 `position: fixed; z-index: 40`。两者是同一 stacking context 下的兄弟节点——`.app-shell` 只有 `overflow: hidden`，**不产生 stacking context**，所以压不住。

触发条件是必然的：设置和各资源面板的入口按钮全长在 `<aside className="sidebar">` 里，手机上要点它们抽屉必须开着，而点完不会自动收起（`setSettingsSection` 旁边没有 `setSidebarCollapsed`）。抽屉宽 `min(88vw, 360px)`，弹窗宽 `min(62rem, 100vw-2rem)`，结果弹窗几乎整个藏在抽屉后面。受影响的不只是设置，人物志 / 历史计算器 / 地图这些资源面板一样。

改成 `z-index: 60`——要同时高过抽屉（40）和书目下拉 `.book-selector-menu`（50）。侧栏折叠按钮那两个 fixed 按钮是 30，也一并被盖住，正确。

**删「保存设置并刷新页面」**

它写的四个键 `ai-settings` / `auto-annotate` / `script-variant` / `custom-actions` 各自都有持久化 effect，点不点都会存；真正起作用的只有清 `caches` + reload。而且这份名单从写下那天起就没跟上过后来新增的设置项（`ui-script-variant`、`mark-style`、`reader-font-color`、主题、字体、字号…）。名字反倒误导用户以为不点就丢。

删完发现 API 配置弹窗底部还有一句「修改后点"保存设置并刷新页面"生效」在指路一个已经不存在的按钮。查了 `runAiAction` 的调用点，`aiSettings` 是每次请求现取 React state 的，改完本来就即时生效，文案改成「修改即时保存并生效」。

## 问题与思考

- **rsync 连着两次被远端掐断**（`Connection to ... closed by remote host`），但 SSH 本身通、服务器无 OOM 记录（dmesg 最后一条还停在 8 月 6 日加 swap）、磁盘 39%。第三次手动跑同一条 rsync 就成功了，看起来是瞬时问题。副作用是脚本在 rsync 那步 `set -e` 退出，**后面的权限修复没跑到**——上服务器一看 `frontend/` 果然又变成 `drwx------`，正是 progress 里记过两次的那个坑。手动补跑了权限修复 + 预压缩。
  - 后来又部署了两轮，**每轮都要重试 2–3 次才通**（`Connection reset by peer` / `closed by remote host`），所以不是偶发，是稳定复现的一个毛病。每次失败都会跳过后面的权限修复，都得手动补。已经不是「值得考虑」而是必须改：rsync 加重试循环，权限修复挪进 `trap`。根因待查（SSH 本身很稳，只有 rsync 传输中被掐）。
- **`/assets/` 现在需要登录**（未登录取 JS/CSS 都是 401）。这和 8 月 6 日记的「放行 /assets/ 和 /fonts/ 给登录页预取」对不上，而且线上 `/login` 页面里也没看到 `rel="prefetch"` 标签。旧 bundle 同样 401，所以不是今天这次部署引入的。冷启动那 15 秒的预取优化目前应该是没生效的状态，待查。
