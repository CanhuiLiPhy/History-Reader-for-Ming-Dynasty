# 2026-10-17 重新打开书时精确回到上次那一页

## 做了什么

- **问题**：重新打开一本书（整页刷新、切走再切回）时，EPUB 常回到前一两页甚至章首，纯文本书则总是回到第 1 章第 1 页。
  - EPUB：保存的位置是 epub.js 的 `location.start.cfi`，对无空格的中文只精确到「首个可见文本节点的开头」，也就是段首；而且它是在年号标注之后的 DOM 上算出的，重新打开时 epub.js 在尚未标注的新 DOM 上解析，文本节点序号对不上（控制台 `No startContainer found`），直接退回章首。
  - 纯文本书：根本没有保存页内位置和章节序号。
- **做法**：在每本书的 `last-location:<slug>` 旁边，另存一条精确位置 `reading-position:<slug>`：页首那个字的全文字符偏移 + 16 字上下文（复用 `reflow-anchor.ts` 的 TextAnchor，不受年号标注 / 划线 span 影响）。
  - EPUB：每次 `relocated` 时随 CFI 一起保存（记录里带上同一个 CFI 与章节 spine 序号）。重新打开时只有「打开所用的 CFI 与记录里的 CFI 完全一致」才恢复，其余情况（检索跳转、旧数据）照旧。先按原逻辑显示，章节渲染完成（年号标注之后）立即校正到锚点所在屏；阅读器就绪时几处「重新显示当前位置」的调用也会再校正；之后再按 120/400/900/1600 ms 和网络字体加载完成各校正一次，最后一次后恢复结束。翻页、跳转等任何导航立即结束恢复。
  - 纯文本书：翻页、滑块、分页重算、滚动稳定时保存「章节序号 + 页首字」。重新打开时直接加载保存的那一章，排版后翻到锚点所在页，网络字体加载完再校正一次。
  - 重排算法本身未改：只读取新算法的锚点；新算法下恢复视同一次跳转（以恢复后那页页首字为新锚点）。
- 新模块 `frontend/src/lib/reading-position.ts`：记录的生成、校验、是否可恢复的判定，纯函数、无 DOM。

## 结果

- `npm --prefix frontend run build` 通过；App.tsx 的 ESLint 问题与修改前完全相同（13 项，全为原有），新模块零告警。

# 2026-10-17（续）切换显示设置时停在原来那一页

## 做了什么

- **问题**：EPUB 阅读时切换「自动年号标注」「正文字体转换（繁简）」「单/双页」，或阅读器就绪时，三个 effect 都用 `openLocation(当前 CFI)` 重新显示。同一章已在显示时 epub.js 不重新渲染、只按 CFI 滚动，而这个 CFI 只精确到首个可见文本节点开头（中文即段首），于是回到段首所在页（常是前一页）。另外年号标注、繁简切换在当前章根本不生效（章节没重新渲染，标注 span 还在），要换章才生效。
- **改前复现**（独立资料副本，1024×768）：《明史》本纪第一第 7/16 页，页首「人望見城西五色雲如車蓋」在段中——关年号标注 → 6/16（段首「秋七月己卯」），文档未重新渲染、标注仍在；切「保留原文」→ 6/16、正文不变；单→双→单 → 6/16。
- **做法**（`frontend/src/App.tsx`）：
  - 章节文档记下渲染时的显示设置（排版方向 | 繁简 | 年号标注）；与当前设置不同就让 epub.js 重新渲染该章，否则只重新显示。
  - 重新显示前先「保持」屏上那个字，复用 10-17 的恢复通道：恢复进行中沿用恢复的字；上一次保持的字（之后没翻页、仍在本屏）沿用；新算法锚点仍在本屏时用它；否则取页首字。显示后、`rendered`（繁简转换与年号标注之后）各校正一次，再按 120/400/900/1600 ms 与字体加载完校正，最后一次结束保持；翻页 / 跳转立即结束。
  - 重新渲染时先隐藏正文（与新算法重排同一机制），校正后再显示；让 epub.js 用不计年号 span 的字级 CFI 定位，不再出现 `No startContainer found`。
  - 保持自然结束后，那个字在读者翻页 / 跳转前仍算阅读位置：下次重新显示再保持它，保存阅读位置时也存它。所以关→开年号标注、单→双→单、双页刷新后再切单页，都回到同一页首字。
  - 阅读器就绪时三个 effect 各重新显示一次：每次显示完都校正到「此刻」保持的位置（以前只校正调用时的那个，后两次会停在段首页）。
  - 两种重排算法本身未改，只读取新算法状态；竖排不保持，沿用 epub.js 定位。

## 结果

浏览器实测（独立资料副本，1024×768，《明史》本纪第一，起点 7/16 页首「人望見城西五色雲如車蓋」，均为单次实测）：

| 操作 | 改前 | 改后 |
|---|---|---|
| 关年号标注 | 6/16 段首；标注没消失 | 7/16 同一字；章节重新渲染，标注消失 |
| 再开年号标注（保持已结束） | — | 7/16 同一字 |
| 繁体 → 保留原文 → 繁体 | 6/16；正文不变 | 7/16；正文变为原文（简体）再变回繁体 |
| 单 → 双 → 单（中间保持已结束） | 6/16 段首 | 双页为含该字的那屏（6/16，字在右栏）；回单页 7/16 同一字 |
| 双页模式刷新，恢复结束后切单页 | — | 7/16 同一字 |
| 新算法：关标注 → 窗口 1024→800→1024 → 开标注 | — | 7/16 同一字 |
| 翻到 8/16 后来回切换 | — | 停在 8/16 |

- 逐帧记录：重新渲染期间正文隐藏，显示出来时已在目标页，没有错页帧；干净加载后的控制台无错误。
- 自动化测试 91 项通过：新增 `frontend/tests/epub-redisplay.test.mjs` 9 项（从 App.tsx 抽取真实代码，模拟 epub.js 队列逐帧执行、分栏版面与年号标注带来的行宽变化）。另做变异检查：逐项拆掉修复的 8 个部分，每项都有用例失败。
- `npm --prefix frontend run build` 通过；App.tsx 的 ESLint 问题与修改前完全相同（13 项，均为原有）。

## 遇到的问题

- 浏览器面板隐藏时 rAF 被节流到约 1 帧/秒（epub.js 队列每帧只跑一个任务），只能核对事件先后，看不出真实耗时。
- 首轮实测发现：保持结束后，双页屏首字已不是原来的字，切回单页会退一页；改为「保持结束后该字仍算位置，直到翻页」后解决。
- 编辑 App.tsx 时 Vite 热更新会重跑所有 effect，出现过一次 `reading 'currentLocation'` 报错（新 rendition 尚无 manager）；整页刷新后不再出现，属开发态现象。
