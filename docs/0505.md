## 二、读通鉴论 章节定位 + 进度条

### 2.1 章节定位（rendered 事件兜底）

epub.js 在某些 `display(href#anchor)` 下不会再 fire `relocated` 事件（比如同 spine 段内换 anchor 它认为没换段就跳过），但 React 状态全靠 relocated 推动 → 章节标题 / 进度条停在前一章末尾。修法：[App.tsx:on("rendered")](../frontend/src/App.tsx) 兜底，比对 `currentHrefRef` 与刚渲染 section 的 href，不一致就 50ms 后读 `rendition.currentLocation()` 自己合成一份「伪 relocated」更新链。

### 2.2 进度条直接 CFI 跳转

旧逻辑：拖进度条 → 一页一页 `rendition.next()` step，60ms 间隔，跳 50 页要 3 秒。改 [App.tsx:jumpToPage](../frontend/src/App.tsx)：算 `targetLocation = currentChapter.locationIndex + (safePage - 1)`，调 `book.locations.cfiFromLocation(targetLocation)` → `rendition.display(cfi)` 一步到位。step 路径仅在 cfiFromLocation 不可用时兜底。

### 2.3 rendition.resize race fix

`ResizeObserver` 在 observe() 时立即 fire 一次回调；如果赶在 `display()` 之前跑，epub.js 内部 `this.manager.resize()` 因 manager 还没建好而抛 `Cannot read properties of undefined (reading 'resize')`，打断 init → 页面长期空白。修法：resize 前检查 `rendition.manager` 存在 + try/catch 兜底。

### 5.1 问题

用户在 明史 本纪7 选「二月己酉」，前文有「十二年春正月庚寅...」（裸年，无年号），按旧 [`lastAnchorBefore`](../frontend/src/lib/reign.ts) 找不到 `<reign>N年` 形式 → 直接放弃 → 显示「查找不到」。

  - 都失败 → null

### 5.3 跨章节 fallback

[App.tsx:handleResolveSelectionDate](../frontend/src/App.tsx) — 在 EPUB / DB-reader 路径都加跨章兜底：

## 六、明实录 干支纪年（重点详记）

明实录不用年号纪年，用干支。一个例子：

> 太祖实录/卷之一 第一段：「**乙未春正月戊午**」 = 元至正十五年（1355年）正月戊午

### 6.1 60 年周期 + 章节 → 年范围

- `ganzhiYearOf(year)` / `ganzhiToYear(干支, from, to)`：60 年周期表
- `SHILU_RANGES` 表：每个实录 prefix → 年份范围段
  - 太祖实录跨度 70 年（1328-1398），拆 1328-1368 元末 + 1368-1398 洪武
  - 其它实录单帝在位都 ≤ 60 年，单段
- `shiluRangesForChapter(chapterLabel)`：前缀匹配返回范围数组

### 6.2 selToken 加 ganzhi-year 类型

`GANZHI_YEAR_RE = /[甲...][子...](?=[春夏秋冬岁歲]|年)/g` —— 干支 后接 季节字 / 年 / 岁 视为干支年（避开 干支 日的 "X日 / 标点" 上下文）。

### 6.3 resolveSelectionDate 加 chapterLabel 参数

命中 ganzhi-year token：
- chapter 在 实录 范围 → 在该范围段内反查 干支 唯一年
- 不在 实录 → 1300-1700 默认窗口 + 用 contextBefore 里的年号名收窄
- 配合后续 月+干支日 一并解析

### 6.4 v1.0.2 重构：完全独立路径 `resolveShiluSelectionDate`

把通用 `resolveSelectionDate` 上的实录污染（chapterLabel 参数 / ganzhi-year token kind / 实录 fallback）全部撤回，新加独立函数 `resolveShiluSelectionDate(selectionText, contextBefore, chapterLabel, mode)`，路径分流：

```
handleResolveSelectionDate:
  inShilu = shiluRangesForChapter(effectiveChapterLabel) != null
  if inShilu:
    resolved = resolveShiluSelectionDate(...)
  if !resolved:
    resolved = resolveSelectionDate(...)  // 通用，未受任何修改
  if !resolved (跨章节兜底):
    重抓上 5 章 → widerContext，对 widerContext 再走相同分流
```

`resolveShiluSelectionDate` 内部识别三种选段：
- (a) 选段含完整「干支+季节(+月)(+干支日)」——自包含
- (b) 选段含「[闰]月+干支日」——年回溯 contextBefore
- (c) 选段只有干支日——年和月都回溯 contextBefore

contextBefore 端找最近的 `SHILU_GZ_SEASON_MONTH_RE`（干支+季节(+月)）锚点。

### 6.5 实录路径仅适用 太祖实录卷1-21

经用户提醒：明实录大部分卷其实正常用 「年号+年」 (永乐X年 / 洪武Y年)，只有 太祖实录前 21 卷（覆盖 朱元璋 出生 1328 至 称帝前一年 吴元年 1367）这段无明朝年号可用，作者刻意以干支纪年。卷 22+ 起进入洪武，跟其它实录无异。

`shiluRangesForChapter` 收窄到只接受 `太祖实录/序` 或 `太祖实录/卷之X`（X 汉字数字 1..21），其余返回 null 走通用路径。年份窗口 `[1328, 1367]`。

### 6.6 关键 corner case：卷 21 开头 + 卷 20 末尾传记

`太祖实录/卷之二十一` 开头是 "丙午八月庚戌朔..."（1366 年），但卷 20 末尾是 廖永安卒 传记，里面回顾了 乙未/甲辰 等更早年份。"text 位置最靠后"挑 anchor 会被传记里晚出现的 "甲辰冬" 误导，"max year" 也可能撞上传记里的回顾。

避免重型识别叙事年 vs 传记年的逻辑，加 [`CHAPTER_DEFAULT_GANZHI`](../frontend/src/lib/reign.ts) 表硬编码补丁：当 selection / contextBefore 都找不到干支年时回退到 `{"太祖实录/卷之二十一": "丙午"}`。其它卷遇到类似 corner case 后续往这张表加映射即可。

### 6.7 跨章节兜底也覆盖实录 + DB-reader

明实录是 DB-reader 书（无 EPUB），`currentSectionLabel` 永远空，`meta` 也为 null。修：
- `effectiveChapterLabel = currentSectionLabel || dbReaderChapter?.chapter || ""`，这样 inShilu 判定能命中
- 跨章节 fallback 的章节列表：`fallbackList = epubList.length ? epubList : dbList (来自 dbReaderChapters.chapters)`
- 跨章节 fallback 后再次 resolve 时也用 `effectiveChapterLabel` 而非 `currentSectionLabel`

## 九、DB-reader 跨段勾画

### 9.1 起因

老逻辑只接受同一段落内的勾画——`handleDbReaderSelection` 在 startPara !== endPara 时直接放弃记录段落锚点，cfi 退化成 `db:slug:idx`（3 段），随后 `addSelectionHighlight` 看 cfi 段数 < 5 就报「跨段勾画暂不支持」。

### 9.2 cfi 格式扩充

新增 8 段「m 标记」格式，老的 5 段单段格式保留：

```
单段： db:<slug>:<idx>:<pid>:<cstart>-<cend>
跨段： db:<slug>:<idx>:m:<pidS>:<cS>:<pidE>:<cE>
```

`handleDbReaderSelection` 同时计算两端段落 ID 与各自段内字符偏移；同段就走老路径，跨段就写 m 格式。

### 9.3 渲染：按段切片包 span

`useEffect [highlights, dbReaderChapter, ...]` 里抽出一个 `wrapRange(para, a, b, item)` 工具：在单个段落内按 `(a, b)` 字符区间走 TreeWalker → `range.surroundContents`。

跨段命中 m 格式时：
- 用 `host.querySelectorAll("[data-paragraph-id]")` 拿全章段落（DOM 顺序 = 文档顺序）
- 找到 startIdx / endIdx
- 头段：`wrapRange(start, cS, paraTextLength(start))`
- 中间段：`wrapRange(p, 0, paraTextLength(p))`
- 尾段：`wrapRange(end, 0, cE)`

每段独立调一次 `surroundContents`，避开「range 跨元素时 surroundContents 抛错」的限制。

### 9.4 兜底

`addSelectionHighlight` 的 < 5 段 bailout 还在，但报错文案改成「无法定位选段所在段落」——只有「连段落都没找到」的极端情况才会触发，跨段不再被这条堵住。

## 十、AI 句读结果叠加到正文

### 10.1 需求

之前 AI 句读只在右侧栏显示，正文上没标记。希望把「红点断句」也直接叠到原文上，但**不存为笔记/勾画**——一次性、瞬态的。

### 10.2 实现思路

句读结果是「原文 + 标点」的字符串。把每个标点视为前一个字的「断句标记」，把标点剥掉拿到 plainAnswer（应等于选段原文），用一个 `Map<plainCharIndex, isStrong>` 记下哪些字位上要画断点。

`buildDudouBreaks(answer)` 扫一遍带标点串：
- `[·。，；：！？、]` 一律算断点
- `[·。！？]` 算「强断点」（句末）
- 多个连续标点合并到前一个非标点字符

### 10.3 选段快照

`performAiAction` 里 `await runAiAction` 之前先 snapshot 当前选段：
- EPUB iframe：保存 `{doc, sc, so, ec, eo}`（4 个 node ref + offset）
- DB-reader：保存当前 `selectionCfi`（5 段或 8 段都行）

`clearSelection()` 会清掉 OS-level selection，但 DOM node 还在；快照拿到的就是这些活节点的引用。

### 10.4 字级 wrap

`applyDudouOverlay(snap, answer)`：
- EPUB / DB 两路分别重建一个 `Range`（DB 路径要根据 cfi 走 paragraph + char-offset 还原）
- 用 `TreeWalker` + `range.intersectsNode` 收集 range 范围内所有 text node
- 对每个 text node：把它在 range 区间内的部分按字符切碎，每个字裹成 `<span class="dudou-overlay-char">`，断点位补 `dudou-overlay-break` (+ `dudou-overlay-strong`)，前后非 range 部分还原成 text node
- 返回 cleanup 函数：unwrap 所有 inserted span，把原始 text node 放回原位 + `parent.normalize()` 合并

### 10.5 cleanup 触发

`dudouCleanupRef` 持有当前 overlay 的 cleanup。下列时机调用 `clearDudouOverlay()`：
- `handleDbReaderSelection` 里检测到新选段
- EPUB rendition `selected` 事件（iframe 选中）
- `useEffect [currentBookSlug, dbReaderIndex, currentChapterIndex]` 的 cleanup（章节/书切换）
- 下一次「AI 句读」开始之前

### 10.6 CSS

`App.css` 里加 `.dudou-overlay-char` / `.dudou-overlay-break` / `.dudou-overlay-strong`，与右栏 `.dudou-card` 用的 `.dudou-char` 同款（红 ·，强断点用 ●），用 `position:absolute` 把红点定在字下方。

EPUB iframe 里 LAYOUT_OVERRIDE_CSS 同样追加这套类，否则 iframe 内不识别。
